## 1. Purpose & Epistemic Separation

V1 connects interactive Propulsion Explorer controls to **validated conventional P0/P1 electrostatic calculations** while enforcing strict epistemic separation:
1. **ESTABLISHED MODEL (COMPUTED):** Quantitative outputs from validated P0/P1 kernels (`parallel_plate_benchmark`, `verify_plate_force_virtual_work`, `electrode_pair_in_grounded_box`, `evaluate_whole_apparatus_force_budget`, and gated multi-resolution diagnostics).
2. **PROVISIONAL ILLUSTRATIVE SCENE (SCHEMATIC — NON-COMPUTED):** The 3D Exodus-inspired knife-edge wedge layout (`W = 160 mm`, `3 mm` thickness, `0.5 mm` tip radius), schematic field streamlines, and `#slider-eps` dielectric proxy. Explicitly non-computed in V1 (`r = 3 mm` in `W = 160 mm` violates `r >= 3h` on every `{41, 81, 101}` grid and would require `n >= 161` under a separate grid/runtime review).
3. **TOY MATHEMATICAL ILLUSTRATION:** Isolated Chapter 5 `scalarWaveGroup` contrast view.

V1 **never** claims whole-body propellantless thrust, **never** maps 2D `N/m` cylinder-in-box results onto the 3D Exodus knife-edge mesh, **never** presents an unbalanced numerical residual as closed force balance, and **always** preserves `WHOLE-BODY THRUST: NOT MEASURED / NOT ESTABLISHED`.

## 3. Domain Eligibility, Contour Topology, Multi-Grid Gating & Force Accounting

### 3.1 Pre-Solve Eligibility & Exact Kernel-Matched Contour Topology (`V1-SPEC-R2-F1`)

Continuous `GroundedBoxConfig` bounds (`abs(cx) + r < W/2`, Euclidean distance `> r_L + r_R`) are insufficient for force evaluation because:
1. `FieldSolution` stores combined `conductor_mask` (not separate `left_mask` / `right_mask`).
2. `evaluate_whole_apparatus_force_budget` (`electrostatics_numerics.py` L415–445) computes horizontal margins using **x-separation** `sep = abs(re.center_x_m - le.center_x_m)` and signed wall checks (`d_left_wall = (le.center_x_m - le.radius_m) - (-W/2)`, `d_right_wall = (W/2) - (re.center_x_m + re.radius_m)`), while `compute_maxwell_stress_contour` (L298–317) snaps bounds via `np.clip(np.argmin(np.abs(coords - b)), 1, n - 2)` and checks perimeter vacuum nodes only.

Without modifying accepted P0/P1 kernels, the V1 adapter enforces **two sequential gates** for every `grounded_box_2d` solve at resolution `n`:

1. **Pre-Solve Grid-Resolved Domain Eligibility Gate (HTTP `400`, `code: "INVALID_FORCE_DOMAIN"`):**
   - `h = box_width_m / (n - 1)` with `n` $\in \{41, 81, 101\}$.
   - Resolved conductor cross-section: `min(le.radius_m, re.radius_m) >= 3.0 * h`.
   - Canonical left-to-right x-ordered clearance (prevents swapped-electrode wrong-wall margins and diagonal contour overlap):
     `(re.center_x_m - re.radius_m) - (le.center_x_m + le.radius_m) >= 6.0 * h`.
   - Four-wall clearances for both electrodes:
     `W/2 - (abs(cx) + r) >= 6.0 * h` and `W/2 - (abs(cy) + r) >= 6.0 * h`.
   - Bounded off-axis UI regime: `abs(cy) <= W / 4.0`.

2. **Post-Solve Kernel-Matched Snapped-Contour Topology Gate (`200` with `force_budget: null` on failure — explicit runtime checks, never Python `assert` statements removable under `-O`):**
   - **Separate Mask vs. Contour Coordinates (`V1-SPEC-R3-M1(a)`):**
     - *Mask coordinates (matching `electrostatics_baseline.py` L488–491):* Recompute `coords_mask = np.linspace(-W / 2.0, W / 2.0, n)` and `x, y = np.meshgrid(coords_mask, coords_mask, indexing="ij")`:
       - `left_mask = (x - le.center_x_m)**2 + (y - le.center_y_m)**2 <= le.radius_m**2`
       - `right_mask = (x - re.center_x_m)**2 + (y - re.center_y_m)**2 <= re.radius_m**2`
       - Validate via explicit runtime boolean checks (failing closed if any fails): `bool(np.any(left_mask))`, `bool(np.any(right_mask))`, `not bool(np.any(left_mask & right_mask))`, `np.array_equal(left_mask | right_mask, sol.conductor_mask)`, and `not bool(np.any(sol.conductor_mask & sol.boundary_mask))`.
     - *Kernel contour coordinates (matching `electrostatics_numerics.py` L293–301):* Recompute `h_sol = sol.grid_spacing_m`, `w_contour = (n - 1) * h_sol`, and `coords_contour = np.linspace(-w_contour / 2.0, w_contour / 2.0, n)` separately from `coords_mask` so half-cell floating-point ties (e.g., `W = 0.04008, n = 41` where `(n - 1) * h_sol != W` in IEEE-754 float64) match the snapped `contour_indices` used by `compute_maxwell_stress_contour` identically.
   - **Exact margin & snapped-box reconstruction:** Compute `margin_x`, `margin_y`, and `wall_margin = 2.5 * h_sol` using the exact formulas of `electrostatics_numerics.py` L415–445, then snap `c_left`, `c_right`, and `c_enclosure_inner` against `coords_contour` to `(ix_min, ix_max, iy_min, iy_max)` via `int(np.clip(np.argmin(np.abs(coords_contour - bound)), 1, n - 2))`.
   - **Strict boolean interior & perimeter invariants (explicit runtime checks):** For each contour box `B = (x0, x1, y0, y1)`, verify `x0 < x1` and `y0 < y1`, build strict interior mask `inside = zeros((n, n), bool); inside[x0+1:x1, y0+1:y1] = True`, and verify:
     - All 4 snapped perimeter edge slices lie 100% in `sol.vacuum_mask`.
     - `c_left`: `int(np.sum(left_mask & ~inside)) == 0` AND `int(np.sum((right_mask | sol.boundary_mask) & inside)) == 0`.
     - `c_right`: `int(np.sum(right_mask & ~inside)) == 0` AND `int(np.sum((left_mask | sol.boundary_mask) & inside)) == 0`.
     - `c_enclosure_inner`: `int(np.sum(sol.conductor_mask & ~inside)) == 0` AND `int(np.sum(sol.boundary_mask & inside)) == 0`.
     - Strict contour disjointness (`x1_L < x0_R or x1_R < x0_L or y1_L < y0_R or y1_R < y0_L`) and strict containment of both `c_left` and `c_right` boxes inside `c_enclosure_inner` (`x0_enc < x0_k` and `x1_k < x1_enc`, and analogously for `y`).
   - **Fail-Closed Rule:** If any post-solve mask or contour check fails, the Laplace field solve may still return `200`, but all force-budget values are withheld (`force_budget: null`, `force_budget_status: "WITHHELD_INVALID_CONTOUR_TOPOLOGY"`, with explicit diagnostic identifying the failed invariant).

## 4. API Schema, Serialization, Interoperable Fingerprint & Worker Failure Policy

### 4.1 Exact Request Schema, Dual Probe Validity, Canonical Provenance & Interoperable Fingerprint (`V1-SPEC-R3-M1(b,c)`, `V1-SPEC-R3-M2`)

- All requests require JSON objects with `additionalProperties: false`. Duplicate JSON object keys (checked via `object_pairs_hook` in Python), booleans (`isinstance(v, bool)`), non-finite numbers (`NaN`, `Infinity`), strings for numbers, and missing required keys fail with HTTP `400` (`DUPLICATE_KEY` / `INVALID_SCHEMA`). Integer fields (`request_id`, `n`, `study_n_list[*]`) accept finite integer-valued JSON numbers (rejecting `bool` and non-integers like `41.5`). Float fields accept finite JSON numbers (`int` or `float`, rejecting `bool`) coerced to IEEE-754 binary64.
- **`POST /api/v1/solve` schema:**
  - `request_id`: required JSON safe integer `1 <= request_id <= 9007199254740991` (`Number.MAX_SAFE_INTEGER`).
  - `mode`: required `"parallel_plate_1d"` | `"grounded_box_2d"`.
  - `parameters`: required object:
    - When `mode == "parallel_plate_1d"`: `{ voltage_v: [0.0, 50000.0], gap_m: [0.005, 0.200], area_m2: [1e-4, 0.05] }` (all required; `probe_xy_m`, `include_convergence_study`, and `study_n_list` rejected with `400` in 1D mode).
    - When `mode == "grounded_box_2d"`: `{ n: 41 | 81 | 101, box_width_m: [0.04, 0.20], left_electrode: ElectrodeSchema, right_electrode: ElectrodeSchema }` where `ElectrodeSchema` requires `{ center_x_m: float, center_y_m: float, radius_m: [0.0015, 0.015], voltage_v: [-50000.0, 50000.0] }`.
  - Optional `probe_xy_m` (`grounded_box_2d` only; default `[0.0, 0.0]`): 2-element finite float list. Outside `[-W/2, W/2]^2` rejects with `400` (`INVALID_PROBE_COORDS`).
  - **Dual Probe Validity Parity (`V1-SPEC-R3-M1(b)`, matching `electrostatics_baseline.py` L656–714):**
    - Evaluate **both** continuous physical membership on `requested_probe_xy_m = [px, py]` (`d_left^2 <= r_L^2`, `d_right^2 <= r_R^2`, or `|px| >= W/2 or |py| >= W/2`) **and** discrete sampled node membership at `(ix, iy) = argmin(|coords_mask - px/py|)` (`bool(sol.vacuum_mask[ix, iy])`).
    - Require `probe_in_vacuum = requested_probe_in_vacuum and sampled_node_in_vacuum`. Note both failure directions (requested physically outside yet snapped onto a conductor node, e.g. `W = 0.04, n = 41, r = 0.0032, left = (-0.008, 0), requested x = -0.00479 -> snapped x = -0.005`, as well as requested physically inside whose nearest node snaps to vacuum).

### 4.2 Strict RFC 8259 Serialization, Synchronous Generation & Error Identity (`R1-M2`, `V1-SPEC-R3-M2`)

- **Serialization & Axes:** Python serializes all responses with `json.dumps(payload, allow_nan=False)`; verifies finiteness on `potential_v` and `ex/ey[vacuum_mask]`; encodes `~vacuum_mask` cells in `ex_v_per_m`/`ey_v_per_m` explicitly as JSON `null` alongside boolean masks; includes `grid_axes: {"coords_m": [...], "shape": [n, n], "axis_0": "x_m", "axis_1": "y_m", "indexing": "ij"}`.
- **Synchronous Pre-Debounce Invalidation & Success/Error Identity Rules (`V1-SPEC-R3-M2`):**
  - Client maintains synchronous tuple `(clientStateGeneration, currentCanonicalFingerprint, activeModelMode, activeViewContext, latestDispatchedRequestId)`.
  - On **every** slider/input change, preset selection, grid resolution change, mode transition (including `A -> B -> A` re-entry), chapter transition, Chapter 5 toggle, `Explore Freely` switch, or offline-fallback transition — executed **synchronously BEFORE starting the `150 ms` debounce timer and independent of any hashing**:
    1. Increment `clientStateGeneration += 1`, compute updated `currentCanonicalFingerprint`, and update `activeModelMode` / `activeViewContext`.
    2. Clear any pending debounce timer (`clearTimeout`) and invoke `AbortController.abort()` on any in-flight `fetch`.
    3. Immediately clear/invalidate live computed readouts and 2D overlays (`solveState = "pending"` or hidden view).
  - Dispatch captures immutable `captured = { gen, reqId, fp, mode, view }`.
  - **Shared staleness gate (evaluated FIRST on both success and error/abort/parse failure):** Callback is current iff `captured.gen === clientStateGeneration && captured.fp === currentCanonicalFingerprint && captured.mode === activeModelMode && captured.view === activeViewContext && captured.reqId === latestDispatchedRequestId`. If false, discard silently (a stale error **never** clears or alters a newer readout or pending state).
  - **Success (`200`) path:** Verify parsed JSON object satisfies `resp.request_id === captured.reqId && resp.input_fingerprint === captured.fp`; if valid, render `solveState = "ready"`; if invalid/malformed while `captured` is current, fall through to current error handling.
  - **Error path (`400`/`408`/`413`/`415`/`429`/`500`/`503`/`504`, network rejection, or malformed JSON):** Validate staleness solely via `captured` against current client state (never requiring `resp.input_fingerprint` or `resp.request_id` on failed/aborted/unparseable responses). When `captured` is current, immediately transition `solveState = "error"`, clear computed readouts, and show error diagnostics so the UI **never** remains stuck `"pending"`.

### 4.3 Local Bridge Isolation, Framed Reads & Fail-Closed Worker Lifecycle (`V1-SPEC-R3-M3`)

In `run_explorer.py`:
- **Strict IPv4 Loopback Allowlist:** `create_server(host, port)` validates `host` $\in \{\text{"127.0.0.1"}, \text{"localhost"}\}$ (`socket.AF_INET` exclusively) and raises `ValueError` for `"::1"`, `"0.0.0.0"`, or external addresses.
- **Origin, Host, Framing & Slow-Read Bounds:**
  - Validate `Host` matches bound loopback host/port and same-origin `Origin` matches `http://127.0.0.1:<port>` or `http://localhost:<port>` on `POST /api/v1/*` (`403` otherwise; **zero** `Access-Control-Allow-Origin: *` headers).
  - Require `Content-Type: application/json` (`415` otherwise); reject missing `Content-Length` (`411`), negative/non-integer/duplicate `Content-Length` (`400`), any `Transfer-Encoding` header (`501`), and `Content-Length > 8192` (`413`).
  - Enforce **wall-clock total header + body read deadline `total_read_deadline_s = 2.0 s`** (`408` on slow-trickle reads) alongside `socket.settimeout(2.0)`.
- **Pre-Thread Admission, Poison Precedence & Fail-Closed Single-Worker Subprocess Lifecycle (`V1-SPEC-R4-M1`):**
  - `ThreadingHTTPServer` (`daemon_threads = True`, bounded active HTTP worker semaphore `max_active_http_workers = 8`; excess concurrent HTTP handshakes rejected immediately with `503`).
  - **Poison Precedence & Shared Single Compute Slot (`max_concurrent_computes = 1`):** Both `POST /api/v1/solve` and `POST /api/v1/study` FIRST check `_worker_poisoned` under the manager lifecycle lock: if `_worker_poisoned` is set, **always reject immediately with `503` (`WORKER_UNAVAILABLE_POISONED`)** (takes strict precedence over `429`, including concurrent callers while poisoned). Otherwise attempt non-blocking `_compute_lock.acquire(blocking=False)`; if already held by an active solve/study, immediately return `429 Too Many Requests`.
  - **Supervisor-Controlled Nonblocking Length-Framed IPC & Single Monotonic Deadline:**
    - Solve/study runs in one persistent isolated child process (`multiprocessing.get_context("spawn")`) communicating over **one dedicated unidirectional pipe pair per worker lifetime** (`(req_r, req_w)` for parent $\to$ worker requests; `(resp_r, resp_w)` for worker $\to$ parent responses via `os.pipe()`), with parent ends `req_w` and `resp_r` set nonblocking (`os.set_blocking(fd, False)`) and driven via `selectors.DefaultSelector`. Never use blocking `multiprocessing.Connection.send()`/`recv_bytes()` or `conn.poll()` on the supervisor side.
    - Every frame on both pipes uses a 4-byte big-endian unsigned integer (`>I`) payload length prefix followed by UTF-8 JSON carrying monotonic per-request `ipc_token` (`uint64`). Framing invariants: `MAX_IPC_REQUEST_BYTES = 16384`, `MAX_IPC_RESPONSE_BYTES = 8388608` (`8 MiB`), and `frame_len == 0` or `frame_len > max_bytes` is treated immediately as malformed IPC.
    - Each request establishes **one single monotonic deadline** `deadline = time.monotonic() + response_deadline_s` (`response_deadline_s = 5.0 s`) governing the entire IPC exchange: lazy worker spawn/startup handshake (if no live worker), incremental nonblocking request write loop (including any backpressure/blocked-send `BlockingIOError` waits), worker computation wait, incremental nonblocking 4-byte response header read + full payload read loop, UTF-8/JSON decode, and exact `ipc_token` match. On every `selector.select(timeout=max(0.0, deadline - time.monotonic()))` wakeup, partial writes/reads advance in memory buffers; if `time.monotonic() >= deadline` before the **complete** response frame is received and verified (whether stalled during request write, stalled during compute, stalled mid-header `1–3` bytes, or stalled mid-body before `expected_len` bytes arrive), the request aborts immediately for bounded teardown.
    - **Worker Channel Lifetime:** A healthy worker reuses its single dedicated pipe pair across sequential requests, strictly delimited by frame lengths and validated per-request `ipc_token`. **On every worker failure, timeout, EOF, or restart/respawn**, old pipe file descriptors are closed and discarded immediately and the next spawned worker receives a brand-new pipe pair (pipes are never reused across worker lifetimes).
  - **Unified Verified Kill/Reap-or-Poison Policy Across All Failure Paths (`worker_reap_timeout_s = 2.0 s`):**
    - Total worst-case **admitted compute, IPC, startup, and teardown** budget (leading up to `504` status generation) is bounded to **`<= response_deadline_s + worker_reap_timeout_s = 7.0 s`**; HTTP header/body read (`total_read_deadline_s = 2.0 s`) and HTTP response transmission are bounded separately and are excluded from this `7.0 s` budget (see `V1-SPEC-R5-I1`).
    - A single shared `_terminate_and_verify_worker(proc, fds)` teardown routine is invoked unconditionally whenever **any** abnormal condition occurs: (a) monotonic `deadline` expires (including blocked send or partial header/body response stall), (b) malformed/zero/oversize frame, UTF-8/JSON decode error, or `ipc_token` mismatch, (c) unexpected `EOF`/pipe error (`BrokenPipeError`, `ConnectionResetError`, unexpected `0`-byte read), OR (d) failed startup/handshake **after** child `Process.start()` created a PID (before first request completes).
    - `_terminate_and_verify_worker` wraps `proc.kill()` in `try/except OSError` (recording kill errors without crashing the HTTP thread), invokes `proc.join(timeout=worker_reap_timeout_s)`, closes and discards all parent pipe FDs, clears the active worker reference, and checks **`proc.exitcode is not None and not proc.is_alive()`**.
      - *If verified dead/reaped:* release `_compute_lock` and return the corresponding error (`504` `SOLVE_DEADLINE_EXCEEDED` for deadline expiry / blocked send / partial-response stall; `500` `IPC_PROTOCOL_ERROR` / `WORKER_CRASHED` for malformed frame, `ipc_token` mismatch, or unexpected EOF; `503` `WORKER_STARTUP_FAILED` for post-spawn startup/handshake failure). Next admitted request lazily spawns one fresh worker with new pipes and zero duplicate live children.
      - *If `proc.kill()` raises unexpected failure or reap check fails (`proc.is_alive()` still `True` or `proc.exitcode is None`):* atomically set **`_worker_poisoned = True`** inside the manager lifecycle lock, **keep `_compute_lock` withheld**, **never** spawn any replacement worker, and fail closed with **`503`** (`WORKER_UNAVAILABLE_POISONED`) for the failing request and every subsequent request (taking precedence over `429`) until process restart.
  - **Synchronized Shutdown:** `server.shutdown()` / `SIGINT` acquires the manager lifecycle lock, prevents concurrent respawns, executes `_terminate_and_verify_worker` (`worker_reap_timeout_s = 2.0 s`) on any active worker, closes IPC handles, and verifies reap status.
  - **Mandatory Implementation Condition (`V1-SPEC-R5-I1` — Executable Spawn FD Transfer, Bounded Startup & Latency Budget Scope):** Per canonical acceptance review [`issuecomment-6898692758`](https://github.com/aguacatero/scalar-wave-viz/pull/18#issuecomment-6898692758), V1 code implementation MUST satisfy and prove all four requirements before V1 code acceptance:
    1. **Supported POSIX FD Transfer & Descriptor Ownership:** Do **not** assume raw `os.pipe()` integer FDs survive `multiprocessing.get_context("spawn").Process` unchanged (CPython POSIX verification showed different pipe inode / `EBADF` when raw pipe FDs are passed directly). Use a supported explicit FD-transfer mechanism (e.g., `multiprocessing.reduction.DupFd` + `detach` or an equivalent explicitly passed-descriptor launch), close unused pipe ends in both parent and child and on all startup failure paths, verify EOF, FD identity/ownership, and zero leaked FDs, and explicitly document supported OS scope (e.g., Linux/macOS POSIX; do **not** claim Windows `selector`-on-pipe support without direct evidence).
    2. **Bounded Startup Launch:** Because CPython POSIX `Process.start()` is synchronous and performs process launch plus blocking bootstrap writes before returning, a `selector` timeout placed after `start()` alone cannot enforce the startup deadline. The implementation MUST bound launch itself (or use a separately supervised launcher/startup design) so the deadline owner performs no unbounded blocking operation, retains ownership of any late-created child, prevents duplicate workers and leaked compute admission while launch/child status is uncertain, and fails closed into `_worker_poisoned` on unverifiable state (including shutdown/respawn races).
    3. **Explicit Latency Budget Separation:** Explicitly distinguish the `5.0 s + 2.0 s` (`<= 7.0 s`) admitted compute/IPC/teardown budget from the `2.0 s` HTTP request header/body read phase and HTTP response transmission; do not claim hard end-to-end HTTP wall-clock latency without bounding every phase.
    4. **Mandatory `V1-SPEC-R5-I1` Fault-Path Tests:** Prove every failure mode in Section 6.1 before V1 implementation review.
